## Chapter 04 - Learning Log :pencil2:

### Overview :brain:
This chapter focused on functions, including how to create and call functions, use parameters and arguments, return values, multiple parameters, and the difference between fruitful and void functions. It also introduced the importance of organizing code into reusable sections and avoiding unnecessary repetition.

### What I learned :sparkles:
- how functions allow code to be organized into smaller, reusable sections
- how to define and call functions using the `def` keyword
- the difference between parameters and arguments
- how parameters act as placeholders while arguments provide actual values
- how multiple parameters allow functions to accept multiple inputs
- how return values allow functions to send results back to the calling code
- the difference between fruitful functions and void (non-fruitful) functions
- how functions can reduce repeated code and improve readability
- how to decide when creating a function is useful and when it may be unnecessary
- how previous concepts such as conditionals and error handling can be combined with functions to create more complete programs

### Hands-on practice :computer:
In this chapter, I practiced:
- creating a pay calculator function that calculates regular and overtime pay
- building a simple calculator using reusable functions
- creating an age calculator with input validation and error handling
- experimenting with parameters, arguments, and return values using small examples
- refactoring code by combining concepts from previous chapters into more organized programs

### Personal notes :thought_balloon:
At the beginning of this chapter, functions felt a little confusing because they introduced a new way of thinking about organizing code. However, after creating small experiments and seeing how functions can be reused, I realized how useful they are when programs become longer and more complex.

One concept that stood out to me was the idea of creating a library of reusable functions. This reminded me of the Page Object Model in test automation, where reusable elements and actions are stored separately to make tests easier to maintain. Functions follow a similar idea by allowing commonly used logic to be created once and reused whenever needed.

I also found the relationship between arguments and parameters confusing at first. After researching the concept, creating examples, and labeling each part of a function call, I was able to understand that parameters are placeholders inside the function definition, while arguments are the actual values provided when calling the function.

Another thing I realized is that learning new concepts does not mean using them separately. Combining functions with previous lessons such as conditionals, user input, and error handling allows programs to become more flexible and closer to real-world applications. Adding new concepts also gives opportunities to refactor code, remove repetition, and make programs shorter, cleaner, and easier to understand.

This chapter helped me appreciate that writing code is not only about making a program work, but also about making it organized, reusable, and easier for others, or my future self to maintain.
